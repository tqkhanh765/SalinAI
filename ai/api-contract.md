# API Contract & Data Schema (v2.0)

## 1. Firebase Realtime Database Schema
All services MUST strictly adhere to this exact JSON structure:

```json
{
  "sensor_data": {
    "salinity": 1.5,       // Float (Unit: ppt - parts per thousand)
    "moisture": 70.0,      // Float (Unit: %)
    "timestamp": "2026-04-09T15:00:00Z"  // ISO String — set by the writer
  },
  "actuator": {
    "valve_state": "OPEN",     // Enum: "OPEN" | "CLOSED"
    "control_mode": "AUTO"     // Enum: "AUTO" | "MANUAL"
  },
  "ai_status": {
    "is_processing": false,    // Boolean — true while AI agent is running
    "last_reasoning": "Salinity is within safe range. No action needed.",
    "alert_sent": false        // Boolean — true if Telegram/Email alert was fired
  },
  "action_logs": {
    // Unique ID generated by push()
    "-NxyZ123456789": {
      "timestamp": "2026-04-09T15:00:00Z",  // ISO String
      "actor": "AI",                          // Enum: "AI" | "USER"
      "action": "CLOSED",                    // Enum: "OPEN" | "CLOSED" | "NO_ACTION"
      "reason": "Salinity spiked to 3 ppt."  // Reasoning string from LLM
    }
  }
}
```

## 2. Backend REST API Endpoints

### `GET /api/health`
Confirms server is alive and Firebase Admin is connected.

**Response `200 OK`:**
```json
{
  "status": "OK",
  "timestamp": "2026-04-09T15:00:00Z",
  "firebase": "CONNECTED"
}
```

---

### `POST /api/chat`
Sends a natural-language query to the LangChain agent and returns the AI's response. Used by the Dashboard chat panel.

**Request Body:**
```json
{
  "message": "Why did the valve close at 14:00?"
}
```

**Response `200 OK`:**
```json
{
  "reply": "At 14:00, salinity reached 3.2 ppt (threshold: 2 ppt). The agent closed the valve to prevent saltwater intrusion.",
  "timestamp": "2026-04-09T15:00:01Z"
}
```

**Response `500 Internal Server Error`:**
```json
{
  "error": "LangChain agent invocation failed.",
  "details": "..."
}
```

---

### `POST /api/override`
Allows the Dashboard to manually set the valve state and/or control mode, bypassing the AI.

**Request Body:**
```json
{
  "valve_state": "OPEN",      // Optional: "OPEN" | "CLOSED"
  "control_mode": "MANUAL"    // Optional: "AUTO" | "MANUAL"
}
```

**Response `200 OK`:**
```json
{
  "status": "OK",
  "updated": {
    "valve_state": "OPEN",
    "control_mode": "MANUAL"
  }
}
```

## 3. Tool / Function Calling Contracts (LangChain Tools)

These are the functions the LLM can invoke during the Agentic Loop:

### `execute_valve_control`
Writes the valve state to Firebase. Only executes if `control_mode === "AUTO"`.

**Input Schema:**
```json
{
  "state": "CLOSED",   // Enum: "OPEN" | "CLOSED"
  "reason": "Salinity exceeded 2 ppt threshold."
}
```

### `check_weather`
Fetches current and forecast weather from OpenWeatherMap for the configured location.

**Input Schema:** _(no parameters required — location is set by env var)_

**Output:**
```json
{
  "condition": "Storm",      // e.g., "Clear", "Rain", "Storm"
  "is_risky": true,          // Boolean — true = proactive valve close recommended
  "description": "Thunderstorm expected in 3 hours."
}
```

### `send_alert`
Sends a notification to farmers/buyers via Telegram Bot or SMTP Email.

**Input Schema:**
```json
{
  "channel": "TELEGRAM",   // Enum: "TELEGRAM" | "EMAIL"
  "message": "⚠️ SalinAI Alert: Valve CLOSED. Salinity at 3.2 ppt."
}
```

## 4. WebSocket Events (Planned — for real-time chat)

> The current MVP uses the `POST /api/chat` REST endpoint.
> A WebSocket upgrade for streaming LLM responses is planned for v2.1.

| Event | Direction | Payload |
|---|---|---|
| `chat:message` | Client → Server | `{ "message": "string" }` |
| `chat:reply` | Server → Client | `{ "reply": "string", "timestamp": "ISO" }` |
| `agent:status` | Server → Client | `{ "is_processing": true/false }` |
